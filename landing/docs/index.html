The problem

Swagger shows endpoints.
It doesn't show behavior.

Vibe-coded backends ship faster than any human can read them. The AI wrote a checkout flow, a payment retry path, a slug-uniqueness guard, a soft-delete cascade — and nobody on the team can recite, line by line, what the system actually does.

You see endpoints in Swagger. You see fields in OpenAPI. You don't see flows. You don't see what happens when login succeeds but the cart is empty. You don't see how the system reacts to twelve near-identical inputs that land on six different code paths. So coverage becomes a stack of near-duplicate Postman collections someone assembles by hand and forgets to update.

What it does

Three primitives. One coverage matrix.

Discover

Attach the inspector as middleware. APICover walks your registered routes — controllers, minimal APIs, attribute conventions — and indexes every endpoint as a draggable node on the canvas. New routes show up the next time the host starts.

Compose

Wire endpoints into business flows on a DAG canvas. Path, query, headers and body accept inline JSONLogic against a live RunContext — pull nodes.login.response.token straight into the next request. No glue code. No bindings layer. Templates resolve at request time.

Branch

Drop a Case Set on any node. Define N variants — different inputs, different headers, different conditions. The engine forks the run at that anchor, deep-clones the context per variant, and runs the downstream subtree once per branch. Variants compose multiplicatively. Each branch reports its own pass/fail.

How it works

A snippet, an attach, a canvas.

using APICover.Inspector;

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddAPICover(opts =>
{
    opts.EnableCallGraphInspection = true;
});

var app = builder.Build();

app.UseAPICover();   // /apicover/ui — open it.
app.MapControllers();

app.Run();
  1. 1

    Attach. One package. One AddAPICover. The middleware mounts at /apicover/ui and discovers your endpoints from the live route table — same source of truth as the framework itself.

  2. 2

    Compose. Drag endpoints onto the canvas. Wire them. Right-click any node to add a Case Set with N variants — { valid, invalid-card, expired-token }, whatever shape your behavior takes.

  3. 3

    Run. The engine topologically schedules nodes, forks at every Case Set anchor, deep-clones the run context per branch, and emits a tree. You get one pass/fail per leaf, plus a coverage matrix you didn't have to build.

  4. 4

    Inspect. Open the Internals tab on any endpoint. APICover walks the IL of the handler, classifies each call (interface, external HTTP, database), resolves DI to the concrete impl, and renders the call graph with PDB file:line annotations. You see what the box actually does — not what its README claims.
