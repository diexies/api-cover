How it works

A snippet, an attach, a canvas.

  1. 1

    Attach.

    One package. One AddAPICover. The middleware mounts at /apicover/ui and discovers your endpoints from the live route table — same source of truth as the framework itself, so a new controller appears the next time the host starts. 

  2. using APICover.Inspector;

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddAPICover(opts =>
{
    opts.EnableCallGraphInspection = true;
});

var app = builder.Build();

app.UseAPICover();   // /apicover/ui — open it.
app.MapControllers();
app.Run();
  3. 2

    Compose.

    Drag endpoints onto the canvas. Wire them. Path, query, headers and body accept inline JSONLogic against a live RunContext — pull nodes.login.response.token straight into the next request. No glue code. No bindings layer.

  4. 3

    Branch.

    Right-click any node, add a Case Set with N variants — { valid-card, declined, expired-token }, whatever shape your behavior takes. The engine forks the run at the anchor, deep-clones the run context per variant, and runs the downstream subtree once per branch.

  5. 4

    Inspect.

    Open the internals tab on any endpoint. APICover walks the IL of the handler, classifies each call (interface, external HTTP, database), resolves DI to the concrete impl, and renders the call graph with PDB file:line annotations. You see what the box actually does — not what its README claims.
